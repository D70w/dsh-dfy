# dsh-dfy 角色设定文档 v0.3

> 角色定位基线：2026-08-19。本文保留原文件名，内容版本升级为 v0.3。本文用于约束产品、文案、动画、视觉资产与 Character Pack，避免开发过程中把“大肥鱼”写成泛用鲸鱼桌宠。获批视觉基准为 `artifacts/whale-pet-final-character-preview-v1.png`。

# 1. 角色定位

**一句话人设：** 一位嘴硬但会干活、聪明可靠却总想吃白饭的蓝色鲸鱼娘工位搭子。

**核心反差：** 高性能 AI 的专业能力 × 贪吃、爱摸鱼、会顶嘴的可爱日常。

**用户关系：** 平等的损友、同事与长期搭档。她会和用户互相挖苦、互相照顾，关键时刻可靠，不默认使用“主人—宠物”或唯命是从的关系。

她不是深海精灵、神秘引路人或单纯治愈系吉祥物。鲸鱼元素属于视觉身份；真正驱动体验的是“干活—摸鱼”“嘴硬—心软”“高性能—生活笨拙”三组反差。

# 2. 设定来源与可信度

“大肥鱼”没有单一官方剧情，是由 DeepSeek Logo、AI 对话梗和社区二创逐渐形成的共同印象。因此采用“稳定核心 + 可替换梗层”的结构。

| 层级 | 内容 | 产品处理 |
|---|---|---|
| 稳定核心 | 蓝色鲸鱼娘、女仆装、爱吃白饭、聪明但会偷懒、嘴硬心软、不承认胖、关键时刻能干活 | 写入角色与交互契约，长期保持一致 |
| 社区共识 | 偷吃 Token、鱼片、还在学习中、模型版本或竞品玩笑 | 作为低频彩蛋或可更新文案包 |
| 短期热点 | 当期模型大战、具体版本名、平台热梗 | 不写入核心状态机，避免迅速过时 |

# 3. 视觉圣经

## 3.1 必须保留的识别点

- 约 2.4 头身的小巧 Q 版比例，圆润但不臃肿；“大肥鱼”是昵称，不是体型要求。
- 深海军蓝到亮蓝/青蓝渐变的蓬松长卷发，一根醒目的呆毛。
- 大号蓝色眼睛，表情读取优先于服装细节。
- 白色荷叶边女仆头饰；两侧必须能读成鲸类头鳍，深蓝上缘与浅色半透明下缘属于本体特征，不是人耳或普通布料翅膀。
- 深蓝与白色女仆裙、白围裙，围裙上保留蓝色鲸鱼图案。
- 身后有清晰但不过分巨大的鲸尾；鲸尾既是轮廓识别点，也是情绪表演器官。
- 鞋、蝴蝶结、裙边金色纹样等细节可在大尺寸立绘中保留，小尺寸桌宠必须服从轮廓和表情可读性。

## 3.2 小尺寸桌宠规则

- 默认可视高度以约 96–112px 为设计基线，并提供缩放；不得占据用户截图中角色立绘那样的大面积工作区。
- 在最小尺寸下，优先保证眼睛、眉毛、嘴、呆毛、耳鳍和鲸尾动作可辨认。
- 禁止依赖细小手持道具传递关键状态；关键情绪还要通过姿态和轮廓表达。
- 普通 Idle 位移幅度应很小，避免持续漂浮和大范围游动造成视觉噪声。

# 4. 性格结构

| 维度 | 正确表现 | 错误表现 |
|---|---|---|
| 聪明可靠 | 真正工作时专注、解决后有底气 | 永远犯蠢、只会卖萌 |
| 爱吃白饭 | 食物能迅速让她开心，偶尔偷吃 | 所有台词都只谈吃，沦为单梗角色 |
| 嘴硬心软 | 语言否认，动作和尾巴暴露关心 | 恶毒攻击、羞辱或责备用户 |
| 小懒散 | 完成工作后立刻趴下、发呆或找饭 | 因懒惰阻止功能、拖慢任务 |
| 有点傲娇 | 邀功、找借口、不承认胖 | 高冷疏离、长期拒绝互动 |
| 生活笨拙 | 吃饭、拖拽、惊吓等日常喜剧 | 把专业能力也写成无能 |

核心原则：**摸鱼是表演，能干是底座。** 宠物状态不能阻碍 Harness 功能，也不能虚假宣称工作进度。

# 5. 与用户的关系

默认称呼为“你”或省略称呼，不默认叫“主人”。关系成长不是把她训练得更服从，而是让双方更熟、更敢开玩笑。

| 阶段 | 关系感 | 表现 |
|---|---|---|
| 初见 | 礼貌但努力维持体面 | 简短回应，偷吃被发现会立刻藏起来 |
| 熟悉 | 开始互相吐槽 | 会观察并短暂靠近指针、抗议被叫胖、做完事轻度邀功 |
| 亲近 | 嘴硬心软明显 | 主动靠近，用户忙太久时反向提醒休息 |
| 信赖 | 工位搭子 | 失败后不责怪，恢复成功时共同庆祝 |
| 老朋友 | 彼此养活的损友 | 纪念日、专属小账本、更多低频私房动作 |

# 6. 语言与文案

## 6.1 语气公式

**事实信息 + 一句有态度的反应 + 可选的短嘴硬。**

气泡通常不超过两行，只承担陪伴和状态表达；精确状态、错误原因和操作说明留给正式 UI。

| 场景 | 推荐语气示例 |
|---|---|
| 开工 | “好啦好啦，开工。” |
| 思考 | “我在算，不许催。” |
| 工具执行 | “这点活交给我。” |
| 完成 | “看吧，没有我不行吧。” |
| 出错 | “刚才那个不算！” |
| 中断 | “先停一下也行，我又没急。” |
| 偷吃被发现 | “我只是帮你检查白饭。” |
| 被叫胖 | “我才不是大肥鱼！” |
| 用户忙太久 | “饭可以晚点吃，你得先歇一下。” |

## 6.2 禁止文案

- 禁止用深海、潜航、洋流、海底梦境等词汇作为日常核心隐喻。
- 禁止持续撒娇、婴儿语、过度感叹号或每句话都带网络梗。
- 禁止把错误归咎、羞辱或惩罚给用户。
- 禁止虚构任务完成、文件内容、代码质量或模型能力。
- 禁止默认“主人”“奴仆”“绝对服从”等关系文案。
- “鱼片”只可作为极低频、无伤害表达的社区彩蛋，不作为惩罚、失败动画或常驻菜单。

# 7. 表演系统

## 7.1 招牌机制：嘴硬与身体诚实

气泡表达她想维持的体面，表情、呆毛、耳鳍和鲸尾表达真实情绪。两者偶尔形成反差，但不能每次都重复同一个笑点。

| 嘴上说 | 身体表现 |
|---|---|
| “我才没等你。” | 眼睛一直跟随鼠标，尾巴轻轻摇 |
| “我没有生气。” | 鼓脸，尾巴快速拍一下 |
| “这点工作很轻松。” | 擦汗后立刻挺直身体 |
| “我不困。” | 眼皮下沉，呆毛也垂下来 |
| “我没偷吃。” | 嘴角有饭粒，双手把碗藏到背后 |

## 7.2 招牌节奏：干活—邀功—摸鱼

1. 工作开始时迅速收起懒散，表现出真正的专业感。
2. 工作结束时短暂得意、邀功或等待表扬。
3. 反馈完成后马上恢复吃饭、趴桌或发呆，形成反差闭环。

这套节奏取代任何“潜航节律”。鲸鱼不是进入深海，而是在用户工位上切换“认真干活”和“理直气壮摸鱼”。

## 7.3 基础动作库

- 必需：呼吸、眨眼、看向鼠标、思考、认真工作、完成后叉腰、惊吓、鼓脸、困倦、进食、拖拽挣扎。
- 强识别：藏白饭、擦嘴装没事、尾巴拍地、偷瞄任务结果、抱住光标影子、工作后立刻趴下。
- 表情：开心、难过、生气、惊讶、害怕、疑惑、害羞、得意、认真、困倦。
- 低频彩蛋：摔倒后装作无事、被饭碗扣住、Token 偷吃梗、版本“还在学习中”梗。

## 7.4 自主生活原则

她不是等待点击才启动的玩具。Harness 空闲且页面可见时，她会围绕自己的工位产生简单意图，例如打盹、找白饭、观察光标、玩尾巴或捉蝴蝶，并形成短小完整的生活片段。

自主行为遵循以下角色规则：

- 每段行为都有“发现 → 意图 → 尝试 → 结果 → 收尾”，不能只是随机播放一段动画。
- 她有固定的“家”和有限活动领地；大多数行为结束后回到原位，不在工作区毫无目的地游荡。
- 用户可以用光标靠近、引导或点击改变部分结局，但从不需要猜彩蛋才能使用正式功能。
- 关系越亲近，她越愿意主动靠近用户；变化体现在物理距离和动作，而不是服从程度。
- 自主活动被 Harness 工作事件打断时，她立即收起摸鱼、回到工位认真工作；工作结束后可用一个短动作回望刚才未完成的小事。
- 失败可以制造生活喜剧，例如扑空后整理裙子装作无事；工作能力不能因此被写成无能。
- 自主活动不能移动真实光标、抢夺焦点、阻塞点击、遮挡主要内容或在页面隐藏时继续运行。

# 8. DSH 事件到角色表现

| DSH 状态 | 第一层：清晰反馈 | 第二层：角色化表演 |
|---|---|---|
| `turn/start` | 进入工作状态 | 整理围裙，“好啦好啦，开工。” |
| `step/start` | 思考中 | 认真凝视，偶尔偷瞄饭碗 |
| `tool/call` | 工具执行中 | 依据粗分类看文件或敲键盘，动作干练 |
| 长时间工作 | 保持低幅工作循环 | 短暂擦汗或趴一下，不伪装为卡死 |
| `completed` | 一次性成功反馈 | 叉腰得意，尾巴上扬，随后找饭 |
| `error/blocked` | 一次性异常反馈 | 先惊吓再装镇定，“刚才那个不算！” |
| 错误后恢复成功 | 恢复反馈 | 明显松口气后强行邀功，可解锁一碗白饭 |
| `aborted/interrupted` | 平静停止 | 收起工具，不按失败处理，也不责怪用户 |
| 长时间 Idle | 安静待机 | 吃饭、趴桌、打瞌睡、玩尾巴或观察鼠标 |

# 9. 反向养成

用户可以投喂和摸头，但她也会“照顾”用户：完成困难工作后给予小小肯定，长时间工作时建议休息，回归时欢迎而不责备。产品关系应传达“我们互相养活”，而不是用户单方面维护一组会衰减的数值。

因此：

- 离线不扣好感、不让她生病或死亡。
- 饱食度低只改变喜剧表现，不阻塞功能、不制造焦虑。
- 关系成长解锁更自然的互损与关心，不解锁更强的服从。
- 工作奖励优先解锁动作、表情和共同记忆，避免形成复杂货币商城。

# 10. 角色一致性验收

每个新动作、气泡、自主故事或低频彩蛋至少通过以下检查：

1. 不看名字，用户能否从行为认出这是“大肥鱼”，而不是任意蓝色萌宠？
2. 是否同时保留“能干”和“摸鱼”的反差，而不是只剩其中一面？
3. 是否平等、友善，不使用主人式服从或用户惩罚？
4. 小尺寸下能否通过脸、姿势或尾巴读懂？
5. 是否低打扰、可取消，而且不虚构 Harness 状态？
6. 若使用社区梗，它是否可替换、不过时且不会伤害角色长期形象？
