# 0. 已确认的体验方向

| 决策 | 结论 |
|---|---|
| 核心价值 | 工位搭子与 Harness 工作联动优先 |
| 打扰强度 | 安静但随时可瞥见；动作多于气泡 |
| 长期动力 | 共同记忆优先；收集为奖励，热点梗为调味 |
| 角色关系 | 平等的损友、同事与长期搭档 |
| 招牌节奏 | 干活 → 邀功 → 摸鱼 |
| 招牌表演 | 气泡嘴硬，表情、呆毛、耳鳍和鲸尾诚实 |
| 自主生命 | 空闲时有自己的意图和短故事；用户经过时可以自然加入 |
| 动作基础 | 参数化角色动作与轻量次级物理；动作可组合、可抢占、可降级 |

# 1. 体验命题

**用户不是在照看一组宠物数值，而是在工作区边缘与一位小同事共同度过一天。**

她平时不争夺注意力。用户从余光中可以看出她是在空闲、思考、执行工具、等待结果、遇到问题还是刚刚完成。只有关键状态、用户主动互动和少量值得记住的瞬间，才出现台词或更明显的表演。

一次完整工作的情绪曲线是：

```text
懒散待机 → 突然认真 → 安静陪跑 → 结果反应 → 嘴硬邀功 → 立刻摸鱼
```

一段长期关系的情绪曲线是：

```text
初见时维持体面 → 熟悉后互相吐槽 → 困难时共同认真 → 成功后共同得意 → 被记住的老朋友
```

# 2. 注意力预算

低打扰不能只靠“减少动画”，而要规定每一种反馈可以占用多少注意力。

| 层级 | 用途 | 表现 | 频率规则 |
|---|---|---|---|
| L0 环境生命感 | 证明她活着 | 眨眼、呼吸、视线、低幅尾巴动作 | 可持续，但单次动作轻微且不带气泡 |
| L1 工作状态 | 让用户从余光读懂 Harness 状态 | 姿势、道具、表情切换 | 每次真实状态变化可触发；相邻事件合并 |
| L2 角色节拍 | 形成记忆点 | 1–4 秒动作，可带一句气泡 | 默认最多 1 次/3 分钟；完成事件可只演动作不说话 |
| L3 主动关心 | 反向养成 | 回归欢迎、休息提醒、低频共同记忆 | 休息提醒最多 1 次/90 分钟；共同记忆最多 1 次/天 |
| L4 用户主动 | 点击、摸头、投喂、打开小账本 | 完整即时反馈 | 不受被动气泡预算限制，但动作需去抖 |

## 2.1 气泡规则

- 默认宽度约 120–180px，最多两行，3–5 秒消失。
- 同一工作回合最多出现一条非用户触发气泡；频繁短回合自动降为纯动作。
- 连续相同状态不重复台词；同一句文案至少经过 30 分钟或一次页面重开才可再次出现。
- 气泡不得覆盖输入框、发送按钮、会话状态栏或右侧文件操作区。
- 安静模式关闭 L2/L3 气泡，只保留 L0/L1 动作与用户主动反馈。

# 3. 首次体验：不用教程弹窗证明价值

首次体验必须在第一次真实 Harness 工作中完成，不使用多页新手引导。

## 3.1 首次出现

| 时间 | 大肥鱼表现 | 用户理解 |
|---|---|---|
| 0–2 秒 | 从右下角边缘探头，确认空间后站好 | 工作区里多了一位角色 |
| 2–5 秒 | 看向鼠标，整理围裙；无气泡 | 她能感知我的存在 |
| 5–10 秒 | 若用户未操作，只进入安静 Idle | 她不会强迫我互动 |
| 首次点击 | “我只是来监督你有没有认真工作。还有，别叫我大肥鱼。” | 性格、关系和称呼梗一次建立 |

首次点击后只显示三个操作：`摸摸`、`一碗白饭`、`安静一点`。基础白饭始终可用，不要求用户先赚取货币或库存；首次有效投喂后的数值收益进入冷却，重复投喂仍有极短反馈但不能刷好感。详情和设置放在二级入口，避免第一眼像管理后台。

## 3.2 第一次真实工作

1. `turn/start`：她快速收起懒散，整理围裙进入工作态。
2. `step/start/tool/call`：用动作证明她与 Harness 联动，不必弹出解释文字。
3. `turn/end: completed`：首次必播得意动作和一句“看吧，没有我不行吧。”
4. 动作结束后，她看一眼空饭碗；饭碗出现轻微高亮，引导用户完成第一次投喂。
5. 用户投喂后，她先快速吃完，再擦嘴装作若无其事；首次体验闭环完成。

这里的投喂教程发生在成功之后，因此用户先理解“她会工作”，再理解“她爱吃白饭”，不会把产品误认为普通养成游戏。

# 4. 一次工作回合的详细体验

## 4.1 状态时序

| 阶段 | 进入表现 | 持续表现 | 离开表现 |
|---|---|---|---|
| Idle | 从上一动作自然收势 | 呼吸、眨眼、观察鼠标、低频偷吃/犯困 | 听见开工后迅速站直 |
| Working | 200–350ms 内整理围裙或拿出小工具 | 低幅循环，不使用大范围位移 | 根据下一状态无缝衔接 |
| Thinking | 眉眼认真、手扶下巴或看资料 | 目光稳定，低频偷瞄饭碗但不破坏专业感 | 工具开始时立即收起思考姿势 |
| Tool | 根据粗分类翻资料、敲键盘或通用工作 | 只表现“正在工作”，不猜测文件内容 | 仍有工具时保持；全部结束后等待结果 |
| Success | 先确认结果，再叉腰或尾巴上扬 | 1.6–3 秒得意/等待夸奖 | 找饭、趴桌或回到安静 Idle |
| Error/Blocked | 先惊一下，随后收敛为认真/疑惑 | 不持续搞笑，不责怪用户 | 若后续恢复，进入专属恢复动作 |
| Interrupted | 收起工具、轻轻叹气或耸肩 | 无失败惩罚 | 平静回到 Idle |

相邻 `thinking/tool/working` 事件使用约 350ms 合并窗口。视觉上应像同一段工作，而不是三个动画不断闪切。

## 4.2 长时间工作

当单次工作持续较久，角色不能看起来卡死，也不能持续高强度敲键盘。

- 0–30 秒：标准认真工作循环。
- 30 秒–3 分钟：在循环中加入一次擦汗、换姿势或确认进度的短动作。
- 3–15 分钟：降低动作频率，偶尔伸懒腰后继续；不弹“还没好吗”之类催促气泡。
- 超过 15 分钟：继续显示工作中，但进入节能表现；只有状态改变才产生明显反应。
- 用户主动点击时，可以嘴硬回应“我在干活，不许催。”，但不能暗示具体完成度。

# 5. 三个招牌体验

## 5.1 招牌一：嘴硬与身体诚实

系统同时选择一个“语言意图”和一个“身体真相”，组合成角色表演。

```text
角色反应 = 系统事实 + 语言态度 + 身体真相
```

| 系统事实 | 语言态度 | 身体真相 |
|---|---|---|
| 用户回来了 | “我才没等你。” | 视线立即跟随，尾巴轻摇 |
| 工作完成 | “这点活很简单。” | 偷偷擦汗后迅速叉腰 |
| 被摸头 | “别把头发弄乱。” | 耳鳍放松，尾巴慢慢摆动 |
| 饱食度低 | “我一点都不饿。” | 眼睛持续瞄向饭碗 |
| 出错后恢复 | “本来就在计划之内。” | 先明显松口气，再恢复得意 |

不是所有事件都要制造反差。约 30% 的角色节拍使用双通道笑点，其余只做清晰自然的状态反馈，避免公式化。

## 5.2 招牌二：错误恢复是共同胜利

普通桌宠通常只庆祝成功；大肥鱼最有价值的记忆点应该发生在“出错后终于恢复”。

1. 第一次错误：惊讶，随后认真；不说风凉话。
2. 连续错误：减少闲散动作，进入专注模式；不增加提醒频率。
3. 恢复成功：肩膀和尾巴先放松，确认无误后才叉腰邀功。
4. 若用户随后点击她：说“我就知道能解决。……刚才紧张的是你吧？”
5. 首次恢复成功写入共同记忆，解锁“刚才那个不算”成就与加蛋白饭。

这一段必须比普通成功多一拍“松口气”，否则用户读不到双方共同经历困难的感觉。

## 5.3 招牌三：反向养成——到底谁在养谁

她不是只等待用户维护。长时间工作、错误恢复和用户回归时，她会反过来照顾用户。

- 连续活跃约 90 分钟：低频提醒“饭可以晚点吃，你得先歇一下。”
- 深夜持续工作：不教育用户，只把自己的困倦投射出来，“我只是有一点困。你肯定也没有吧？”
- 离开数日回归：不扣数值、不责备，“你回来啦。先说好，我可没一直等。”
- 困难恢复：给予短暂肯定，不把全部功劳抢走。

所有主动关心均可单独关闭；关闭后不影响好感度和成就。

# 6. 自主生活：真正建立陪伴感的地方

Idle 不是随机动画播放器，而是角色在工位上的生活。用户即使长时间没有点击她，也会看到她产生自己的小目标、尝试行动并收尾；用户经过时可以自然加入，但不会被强迫互动。

**自主体验命题：** 她不是等待点击才启动的玩具，而是平时有自己的生活；用户经过时，可以自然加入她正在发生的故事。

## 6.1 先判断用户处境

“用户没点宠物”不等于“用户离开”。自主系统综合 Harness 状态、页面可见性、指针活动和宠物互动判断场景。

| 场景 | 判定示例 | 允许行为 |
|---|---|---|
| 工作中 | Harness 为 working/thinking/tool | 只保留 L0/L1 生命感与工作动作，禁止离开工位 |
| 陪伴空闲 | Harness idle，指针仍在活动 | 玩尾巴、观察指针、整理裙摆、局部小剧场 |
| 真正离开 | Harness idle，指针与键盘均长时间无活动 | 打盹、趴桌、安静吃饭；不弹气泡 |
| 页面隐藏 | `document.hidden=true` | 暂停所有非必要动画和自主计时，不补播错过的小剧场 |

不得通过读取 DSH 私有 DOM、输入内容或按键文本判断用户行为；只使用页面级活动信号和已正式接入的 Harness 状态。`pointermove`/`keydown` 只更新内存中的最后活动时间，不保存坐标轨迹或键值；指针采样节流到不高于 10Hz，页面隐藏或组件卸载时立即移除监听。

## 6.2 Idle 动作层级

| 类型 | 示例 | 建议间隔 |
|---|---|---|
| 微动作 | 眨眼、呼吸、视线移动、呆毛轻晃 | 3–12 秒，错峰发生 |
| 常规动作 | 整理裙摆、看指针、玩尾巴、轻微犯困 | 30–90 秒 |
| 生活动作 | 吃白饭、趴桌、短暂睡着、擦嘴装没事 | 3–8 分钟，页面可见时才调度 |
| 主动拜访 | 走到指针安全距离、坐下陪伴 | 最多 1 次/10–15 分钟 |
| 完整小剧场 | 捉蝴蝶、饭碗扣头、摔倒装镇定 | 每日 0–2 次 |

一次明显表演结束后至少留出 20–40 秒纯微动作时间。同一时间只允许一个自主剧场和最多两个短暂场景道具，避免堆叠成视觉噪声。

## 6.3 自主意图模型

系统先选择意图，再选择适合当前状态的故事模板，最后根据用户介入决定结局。

```text
AutonomyEpisode = 发现目标 → 产生意图 → 尝试行动 → 得到结果 → 角色化收尾
```

| 意图 | 典型条件 | 可用故事 |
|---|---|---|
| rest | 精力偏低、真正离开 | 犯困、找抱枕、趴桌、惊醒后否认 |
| eat | 饱食度偏低、基础白饭冷却允许或特殊食物可用 | 偷吃白饭、藏碗、擦嘴装没事 |
| play | 心情较好、陪伴空闲 | 玩尾巴、捉蝴蝶、追小光点 |
| approach | 关系达到熟悉、指针停留 | 观察、犹豫、靠近指针、坐下陪伴 |
| tidy | 拖拽或摔倒后 | 整理围裙、扶正头饰、假装无事发生 |
| wait | 用户离开但工作状态已结束 | 守在结果旁、等用户回来后再反应 |

意图权重受精力、心情、饱食度、关系阶段、当天触发次数和最近故事影响，但不能改变角色稳定核心。不得为了播放故事伪造等待、延迟真实结果或主动消耗用户资源。

## 6.4 家与活动领地

- 用户最后确认的位置是 `homeAnchor`。自主行动从这里出发，大多数行为结束后返回这里。
- 默认“守在工位”模式的活动半径约 160–240px；角色不穿越中央工作内容追逐目标。
- 可选“偶尔散步”允许她沿窗口底边和侧边安全带移动，但仍禁止遮挡输入区和关键控件。
- 指针拜访仅在指针也位于同一窗口安全边缘带时发生；不跨越中央内容追逐用户。最远距离、路线和停留位置必须经过安全区约束。
- 安全区不依赖 DSH 私有 class 或层级；可以用通用语义规则排除 `button`、`a`、表单控件、`[contenteditable]` 与可聚焦元素。命中排除区时直接取消故事，不尝试穿越或绕行。
- 窗口缩放、侧栏变化或浏览器 zoom 后重新计算领地；找不到安全路线时取消故事并回到 clamp 后的 homeAnchor。
- 当前视口内的 `homeAnchor`、clamp 结果与临时领地边界属于设备/视口状态，保存在 Client Store；换设备后可以回到各自安全位置，不写入角色人格。
- “偶尔散步”“偶尔来找我”等用户选择属于长期体验偏好，由 DSH Settings 保存；它们可以随用户设置恢复，但每个浏览器仍根据自己的视口、安全区和 reduced motion 决定本次是否执行。

## 6.5 鼠标关系与主动拜访

- 指针进入角色附近约 120px：眼睛先跟随，不立即弹气泡。
- 悬停约 1.5 秒：身体略微转向，表示注意到了用户。
- 快速划过：只移动视线，不转身追逐。
- Harness 空闲、指针位于安全边缘带且停留约 2 秒时，她才可能主动靠近。
- 她停在指针外侧约 40–64px，绝不站到热点正下方；指针开始点击、拖动或快速移动时立即停止靠近。
- 初见只远处观察；熟悉后装作路过；亲近后可以坐在旁边；老朋友才低频抱住“指针影子”一秒。
- 自动移动阶段的角色层使用 `pointer-events: none`，因此只接受指针接近/远离造成的分支，不接受直接点击；稳定停下并确认不覆盖通用交互元素后，才恢复角色自身交互热区。不得通过事件转发或模拟点击绕过这一限制。

她不会无限追踪指针。用户移动后最多追一小步，随后停下鼓脸或返回工位。

## 6.6 可分支小剧场

### 捉蝴蝶

1. 蝴蝶只在角色周围约 150–240px 的小舞台出现，不能把她引过中央工作内容。
2. 发现阶段约 300–400ms：眼睛先锁定，头部随后转向，呆毛和耳鳍最后暴露兴奋；角色本体不移动。
3. 接近阶段约 600–900ms：她压低身体、踮脚走一至两步，中间保留一次停顿确认，避免像自动追踪器。
4. 蓄力与扑击约 500–700ms：身体先压缩再沿短弧线扑出，双手合拢、裙摆和鲸尾延迟跟随；用户不介入时也能得到完整结局。
5. 用户用指针靠近蝴蝶时，只改变蝴蝶下一段路径。缓慢把蝴蝶赶向她可提高抓到概率；突然冲向蝴蝶会令它受惊，她扑空后看向指针。
6. 抓到后，她先得意展示，发现蝴蝶挣扎后又装作随手地放走；扑空后短暂停住、观察用户是否看见，再迅速整理裙子。
7. 连续两次失败后下一次保证成功，但结果不产生工作奖励、稀有资源或可信成就，只形成有界的剧情记忆。
8. 全段通常 3–5 秒、最长不超过 6 秒；Harness 开工时立即放弃蝴蝶并进入工作，工作结束后最多回望蝴蝶离开的方向一次。

### 打盹

1. 轻困从眼皮、呆毛和尾巴开始，不立即出现道具。
2. 真正离开时才进入趴桌或抱枕熟睡。
3. 指针靠近时先睁一只眼偷看；摸头后嘴上否认睡觉，身体仍摇晃。
4. Harness 开工时猛然惊醒、整理围裙，装作一直在等待。

### 偷吃白饭

1. 先环顾四周，再从身后拿出饭碗。
2. 用户不靠近时正常吃完并擦嘴。
3. 指针突然靠近时立刻藏碗；若来不及，嘴角留下短暂饭粒痕迹。
4. 当天再次偷吃时，若上次被发现，她会增加一次回头确认动作。

分支只是增加参与感，不隐藏正式操作。用户始终可以通过快捷菜单明确执行“叫她过来”“投喂”或“安静一点”。

## 6.7 打断与行为连续性

自主剧场必须可在任意步骤安全中断。

| 打断来源 | 处理方式 |
|---|---|
| `turn/start` | 立即进入“收起摸鱼 → 回到 homeAnchor → 工作”过渡；优先级高于故事收尾 |
| 用户点击 | 仅在角色静止且交互热区已恢复时接入分支；移动中不截获底层页面点击 |
| 用户拖拽 | 取消当前路径和场景目标，保留可安全携带的姿势状态 |
| 页面隐藏 | 冻结或取消，不在恢复后补播旧故事 |
| 视口变化 | 重新求安全位置；失败则无声回家 |

`EpisodeResumeToken` 只保存非敏感、短寿命的故事状态，例如“刚才蝴蝶跑掉了”或“偷吃被发现”。工作结束后最多回调一次，超过 10 分钟或页面重开即过期；不得让旧彩蛋压过当前状态。

## 6.8 关系改变物理距离

| 关系阶段 | 自主空间行为 |
|---|---|
| 初见 | 留在工位，远处观察指针 |
| 熟悉 | 偶尔走近，被看见就装作路过 |
| 亲近 | 坐在指针安全距离旁，愿意分享当前小剧场 |
| 信赖 | 用户工作或遇错时更愿意靠近陪坐，但不遮挡内容 |
| 老朋友 | 极低频抱住指针影子、在旁边打盹或把抱枕推向用户 |

关系只提高“愿意靠近”的概率，不突破安全距离、频率预算和安静模式。

## 6.9 短暂痕迹与日常习惯

- 行为可留下 10–30 秒的轻量痕迹：一粒白饭、歪掉的头饰、脚边抱枕或蝴蝶留下的小光点。
- 痕迹用于连接前后动作，不承载关键状态；同一时间最多两个，页面隐藏立即清理。
- 她可以根据本地、安全的聚合习惯调整权重：常见活跃时段、用户常喂食物、互动频率和安静模式使用习惯。
- 习惯只改变出现时机与动作选择，不生成未经确认的用户画像，也不读取工作内容。

## 6.10 召唤与婉拒

- 快捷菜单提供明确的“叫她过来”和“回工位休息”。光标小手势只作为彩蛋，不是唯一入口。
- 被召唤后，她走到安全距离、短暂陪坐，再根据状态返回或留下。
- 用户选择“安静一点”或把她放回抱枕区域后，她停止主动拜访和 L2/L3 气泡，不扣好感。
- 即使处于安静状态，关键 Harness 状态仍通过低幅 L1 动作表达。

## 6.11 连续与稀有故事

长期故事只保存少量离散标记，不显示任务进度，也不要求用户完成。

- 连续几次抓不到蝴蝶，之后首次成功时出现不同收尾。
- 饭碗扣头后，下一次使用同一饭碗会先谨慎观察。
- 用户持续工作时她先睡着，醒来发现用户还在，便把抱枕推向指针方向。
- 错误恢复得到加蛋白饭后，下次恢复时会下意识看饭碗，再嘴硬移开视线。

单个连续故事最长跨 7 个活跃日，随后自然过期，避免存档长期累积大量情节债务。

## 6.12 多标签页与唯一表演者

- 同一浏览器 profile 的多个 DSH 标签页优先通过 Web Locks 选出一个可见、获得焦点的“表演主标签页”；不支持时再使用 `BroadcastChannel` 与短租约降级。
- 只有主标签页运行 L2/L3 自主故事并提交 `record-story-outcome`；其他标签页只显示 L0/L1 状态反馈，避免同一故事重复记忆。
- 主标签页隐藏、失焦或关闭后释放租约；新标签页接管时从稳定 Idle 开始，不迁移正在播放的 Episode。
- 不支持 `BroadcastChannel` 时降级为“各标签页只本地表演、故事结果不持久化”，不能冒险重复写入长期记忆。

## 6.13 用户离开后的结果收据

- 用户只是停止操作但页面仍可见时，Harness 结果照常播放一次；随后角色可保持对应的低幅姿势或一个小书签，最长 10 分钟。
- 页面隐藏期间不播放完成/错误动画。恢复可见后，只在 `changedAt` 距今不超过 5 分钟且 `causeSeq` 未处理时显示一条静态“结果收据”，不重播庆祝、不重复结算奖励。
- 超过时限、刷新页面或会话已切换时直接显示当前稳定状态；历史事实只进入工位小账本。

# 7. 用户主动互动

## 7.1 可发现的基础操作

| 操作 | 反馈 | 设计目的 |
|---|---|---|
| 单击角色 | 看向用户并随机短回应 | 最低成本建立存在感 |
| 点击头部/“摸摸” | 害羞、躲开或嘴硬放松 | 表达关系阶段 |
| 拖拽身体 | 轻微挣扎；放下后整理围裙 | 调整位置同时保持角色感 |
| 双击 | 打开紧凑详情浮层 | 给熟悉用户快速入口 |
| 右键/长按 | 打开快捷菜单 | 提供明确操作，不依赖隐藏手势 |
| 投喂白饭 | 进食动作和口味记忆 | 强化角色识别而非经济优化 |
| 叫她过来 | 走到指针安全距离并短暂陪坐 | 让主动拜访可被明确召唤 |
| 追赶蝴蝶 | 立即播放完整追逐、扑击和回位演出 | 允许用户主动欣赏与检查招牌动画，不影响长期故事统计 |
| 回工位休息 | 返回 homeAnchor，停止主动靠近 | 给用户比“隐藏”更温和的婉拒方式 |

拖拽判定需要和点击分开：移动超过 5–8px 才进入拖拽；按下区域内的菜单控件不触发拖拽。拖拽后保留至少 24px 可抓取区域在视口内。

## 7.2 互动冷却不是拒绝

连续点击时，不能每次都播放完整动作，也不能冷冰冰地无响应。

- 第一次：完整动作 + 可选气泡。
- 2–3 秒内再次点击：只转眼或尾巴轻拍，表示“听见了”。
- 连续点击达到阈值：鼓脸或护住头部一次；不扣好感、不训斥用户。
- 进入冷却后仍保留极短视觉确认，避免用户误以为界面坏了。

# 8. 关系与共同记忆

## 8.1 关系不是经验条

好感度可以在详情中存在，但首层体验只显示关系称谓：`初见`、`熟悉`、`亲近`、`信赖`、`老朋友`。升级不弹大型庆祝页，而是在下一次合适情境中自然出现一个新动作或新口吻。

例如：达到“亲近”后，不立即告诉用户“解锁休息提醒”；等下一次长工作时，她第一次主动关心，用户会感到关系真的变化了。

## 8.2 可保存的安全记忆

| 记忆 | 数据来源 | 未来回调方式 |
|---|---|---|
| 第一次见面 | 时间戳 | 周年/百日纪念 |
| 第一次完成回合 | 事件序号 | 首周小账本 |
| 第一次错误后恢复 | 相邻结果状态 | 专属成就与恢复动作 |
| 共同完成回合数 | 聚合计数 | 低频里程碑 |
| 常见活跃时段 | 本地小时分桶 | 夜间/白天口吻微调 |
| 最常投喂食物 | 投喂计数 | 进食台词和小账本 |
| 回归间隔 | 最后活跃日期 | 不责备的回归欢迎 |
| 互动风格 | 点击/摸头/投喂比例 | 微调主动靠近与互损权重 |
| 自主故事标记 | 捉蝴蝶、偷吃、打盹等离散结果 | 形成一次短期回调或稀有结局；自动过期 |

禁止保存项目名称、文件名、代码、Prompt、终端内容或用户对话文本。共同记忆的价值来自“我们经历过”，不是“宠物偷看了工作内容”。

## 8.3 一周体验节奏

| 时间 | 用户发现的新东西 |
|---|---|
| 第 1 天 | 她会响应真实工作，也爱吃白饭 |
| 第 2 天 | 发现一两个安静 Idle 生活动作 |
| 第 3 天 | 首次看到错误恢复的完整情绪弧 |
| 第 4–5 天 | 她开始记住互动和常喂食物，口吻略有变化 |
| 第 7 天 | 生成第一份周度工位小账本，突出共同经历而非签到 |

不能为了填满七天强制每天解锁内容。若用户没有触发某种真实经历，相应内容延后自然发生。

# 9. 工位小账本

小账本分为“事实”和“大肥鱼批注”两层。

```text
今天：3 个回合完成，1 次中断，1 次错误后恢复。
大肥鱼批注：最后还不是解决了。刚才紧张的肯定不是我。
```

## 9.1 信息层级

1. 今日一句话：最值得记住的共同事件。
2. 事实摘要：回合结果、工作时长区间、互动与投喂次数。
3. 大肥鱼批注：从安全模板生成的一句角色化评论。
4. 长期里程碑：仅在发生时出现，不制造连续签到压力。

小账本不自动弹出。首次周报仅在角色旁出现一个小书签提示，用户主动打开后才展开。

# 10. 详情浮层与设置

## 10.1 详情浮层

详情不使用四条醒目的游戏化进度条占据首屏。默认先展示自然语言状态：

```text
刚吃饱 · 心情很好 · 有点困 · 已经是熟悉的工位搭子
```

建议结构：

1. 角色当前状态与关系称谓。
2. 三个快捷操作：摸摸、白饭、休息。
3. 今天的事实摘要与最近共同记忆。
4. 次级入口：工位小账本、成就、设置。

精确数值可放在“详细信息”或无障碍文本中，不作为主要视觉焦点。

## 10.2 用户能理解的设置

| 设置 | 默认 | 用户文案 |
|---|---|---|
| general.quietMode | 关闭 | 安静一点 |
| bubble.enabled | 开启 | 允许她偶尔说话 |
| reaction.workEnabled | 开启 | 跟随工作状态 |
| reminder.breakEnabled | 开启 | 忙久了提醒我 |
| dialogue.communityMemes | 开启 | 偶尔玩社区梗 |
| progression.autoEat | 关闭 | 饿了可以自己吃 |
| autonomy.enabled | 开启 | 允许她自己玩 |
| autonomy.cursorApproach | 开启 | 偶尔来找我 |
| autonomy.roamingMode | 关闭 | 偶尔沿窗口边缘散步 |
| animation.reducedMotion | 跟随系统 | 减少动作 |
| audio.enabled | 关闭 | 声音 |
| locale | 跟随界面 | 语言 |

桌宠快捷菜单与 Harness 设置页必须操作同一份 DSH Settings：修改后立即生效，不要求刷新，也不能分别维护两套开关。位置、面板开合等当前浏览器状态不出现在跨设备偏好中；饱食度、关系、库存和共同记忆则进入宠物存档，三类数据在体验上保持一致、在技术上严格分层。

不在设置首页暴露 `Session Projection`、`causeSeq`、`hunger decay` 等技术术语。

# 11. 异常和边界状态

| 情况 | 角色表现 | 正式 UI |
|---|---|---|
| Host 暂时断开 | 角色疑惑地查看工具，停止状态推断 | 显示“暂时无法获取工作状态” |
| 存档失败 | 本次动作照常播放，但不伪装为已保存 | 显示“本次变化未保存”，提供重试 |
| 多会话同时工作 | 当前会话决定主动作，后台忙碌只用小幅提示 | 详情可显示“后台还有会话运行” |
| 多标签页同时打开 | 只有获得租约的可见标签页运行并持久化自主故事 | 其他标签页保留基础状态，不重复写入 |
| 页面缩放/窗口变小 | 自动 clamp 到安全位置 | 不要求用户手动找回角色 |
| 长时间页面隐藏 | 暂停非必要动画与自主故事 | 恢复后不补播过期反应 |
| 用户频繁完成短回合 | 合并成功表演，降低气泡频率 | 统计仍按真实事件累计 |
| reduced motion | 使用表情、透明度和静态姿态切换 | 所有信息仍可读 |
| 自主故事中途开工 | 无条件收起故事并返回工作；可保留一次短寿命回调 | 不延迟或遮挡真实状态 |
| 路径或安全区不可用 | 取消移动，以原地动作替代 | 不跨越内容、不瞬移到未知区域 |

错误状态必须先清晰后可爱。角色笑点不能掩盖连接失败、存档失败或 Harness 异常。

# 12. 动画与表情最低内容量

## 12.1 MVP 必需动作

| 类别 | 最低动作 |
|---|---|
| 生命感 | 呼吸、眨眼、视线跟随、尾巴轻摆 |
| 工作 | 开工整理、思考、通用工具、长工作换姿势 |
| 结果 | 普通成功、错误惊讶、中断收尾、错误后恢复 |
| 互动 | 点击回应、摸头、拖拽挣扎、放下整理、吃白饭 |
| Idle | 趴桌/犯困、玩尾巴、偷吃或擦嘴装没事 |
| 自主剧场 | 捉蝴蝶、指针拜访、可中断回工位各至少一组 |
| 关系 | 初见、熟悉欢迎、亲近关心至少各一组 |

## 12.2 文案池最低数量

- 工作开始：8 条。
- 思考/工具：各 8 条，但默认大部分事件静默。
- 普通成功：12 条。
- 错误/阻塞：各 8 条，禁止责怪用户。
- 错误后恢复：10 条，应区别于普通成功。
- 点击/摸头/投喂：各 12 条，并按关系阶段分组。
- 回归：按 1 天、2–7 天、7 天以上各 6 条。
- 休息提醒：8 条，不使用恐吓健康后果的措辞。
- 自主故事：每类以动作承担主要表达，文字最多 4–6 条低频收尾；不得让气泡替代故事表演。

文案数量不是为了频繁说话，而是避免低频气泡仍然迅速重复。

## 12.3 动画资产交付契约

每个动作在进入实现前必须提供以下信息，不能只交付一段无法安全打断的成片：

| 字段 | 要求 |
|---|---|
| key poses | 起始、识别姿势、结果、回归至少四个关键姿势 |
| duration | 推荐时长与可缩短范围 |
| interrupt points | 动作提示点与自然转场点；工作事件不等待提示点，可从任意时刻抢占 |
| hitbox | 静止交互热区；移动阶段默认无热区 |
| parameters | 需要驱动的头部、视线、表情、手臂、身体与次级物理参数 |
| cues | 起跳、合手、落地、拿出饭碗等需要与道具同步的命名时间点 |
| prop layers | 饭碗、蝴蝶、抱枕等独立层、角色挂点及清理时机 |
| reduced-motion | 静态姿势/表情替代，不依赖位移传达状态 |
| mirrored use | 能否镜像；文字、徽记和左右不对称装饰禁止错误镜像 |

MVP 使用 WhaleRig 的混合动作轨：待机、工作和轻表情由完整正面角色上的局部网格、参数曲线与次级弹簧承担；跑步等会改变手脚位置、轮廓和遮挡关系的动作使用从同一连续母带提取的短姿态序列。序列帧不是不可抢占的视频：它仍由 Motion JSON 选择当前姿态，共享命名提示点、舞台 Pivot、镜像、位移时钟和中断规则。道具始终是独立 Actor，不烘焙进角色帧。

捉蝴蝶是首个完整动作管线验收故事：同一套发现、视线追踪、接近、扑击、整理和回工位能力必须能够被其他故事复用。它通过后，才能继续扩充更多自主剧场，避免先堆素材再补抢占和清理能力。

当前实现状态（2026-08-19）：捉蝴蝶、指针拜访与打盹三个闭环已经落地，共享 `notice → intend → attempt → result → recover → return-home`。独立生成、比例和锚点不一致的动作表以及拼接式侧面 rig 均已退出 manifest。Character Pack v2 采用“双轨混合”：正面静态轨使用 18×18 局部网格、9 个影响区、18 个有界参数与 5 条阻尼弹簧；侧身跑步轨使用同一连续母带中 1.50–4.50s 的稳定闭环，提取 24 个透明完整姿态，在统一 112×112 舞台中真实表现双脚交替、手臂摆动、头发后拖、裙摆开合与鲸尾拍动。`runFrame` 以 30ms 离散步进形成 720ms/约 33fps 循环，外层位移仍是 60FPS；22px 实际路程严格推进一个完整周期，因此追蝴蝶、指针拜访和回工位跨故事阶段仍连续且不积累脚滑。正面/跑步轨以 120ms 透明度过渡，帧选择器不做浮点混合。蝴蝶保持独立 SVG Actor。合格跳跃素材验收前只组合 `ready/run`，不伪造蹲跳、滞空和落地。

## 12.4 无障碍、窄窗口与本地化

- 自主道具和蝴蝶默认 `aria-hidden=true` 且不可聚焦；稳定的宠物主控件是唯一键盘入口。
- 键盘焦点进入宠物或菜单时立即取消自主移动并返回安全静止姿势；菜单关闭后焦点回到触发控件。
- 装饰性气泡不进入 live region；只有连接/存档等关键状态使用 `aria-live=polite`，同类消息去重。
- `prefers-reduced-motion` 下关闭散步、指针拜访和追逐位移；改用原地视线、表情与姿势切换，不能用突然瞬移替代动画。
- 触摸/粗指针设备不依赖 hover 和光标故事；主控件及菜单触控目标至少 44×44 CSS px。
- 默认面向桌面 Web。视口宽度小于 1024px 时关闭散步并缩小领地；小于 768px 时角色基线降为约 80–96px，只保留 homeAnchor 附近动作。
- 所有 UI 与台词使用 locale key，不把文本画进图片。v0.1 至少完整交付 `zh-CN`；未完成的语言回退到中性、准确的状态文案，不混用半翻译角色台词。
- 气泡和菜单为文本扩展预留约 40%，在 200% 浏览器缩放、长 CJK/Latin 文本与 emoji 下不得溢出视口。

# 13. 验收场景

## 13.1 五分钟体验测试

新用户在没有说明书的情况下，应能说出：

- 她会跟随 Harness 的工作状态。
- 她有点懒、有点嘴硬，但工作时很可靠。
- 她喜欢白饭，而且不喜欢被叫胖。
- 她不会妨碍输入，可以拖走或安静下来。

## 13.2 一小时工作测试

- 用户没有因为气泡或大动作主动隐藏她。
- `thinking/tool/working` 不闪烁，长工作也不会看起来卡死。
- 多次短回合不会导致成功动画和台词轰炸。
- 至少一次从余光可读的工作状态变化，无需打开详情。
- 自主故事开始后遇到工作事件能立即、自然地回到工作，不残留阻塞点击的道具或热区。

## 13.3 一周陪伴测试

- 用户能回忆至少一个具体共同经历，例如首次恢复错误，而不仅是“她很可爱”。
- 小账本记录准确，不包含工作内容和隐私字段。
- 关系变化体现在动作与口吻，不只是数值增长。
- 离开几天后回归没有惩罚、责备或强制补做内容。

# 14. MVP 体验优先级

## P0：没有这些就不是本产品

- 96–112px 的清晰小尺寸角色。
- Idle、Working/Thinking、Success、Error、Recovery 五类可辨状态。
- 干活 → 邀功 → 摸鱼的完整节奏。
- 嘴硬与身体诚实的双通道表演。
- 低打扰预算、气泡限频、安静模式。
- 拖拽、点击、摸头、白饭投喂。
- 错误后恢复的专属动作。
- 自主意图、homeAnchor 和安全领地。
- 捉蝴蝶、指针拜访、打盹和显式召唤/回工位作为首批端到端可中断体验；继续复用同一意图、动作、展示权和清理能力实现偷吃白饭。

## P1：形成长期关系

- 工位小账本。
- 安全共同记忆。
- 关系阶段与自然解锁。
- 回归欢迎与反向休息提醒。
- 自适应表达权重。
- 关系距离变化、短期 EpisodeResumeToken 和稀有连续结局。

## P2：增加新鲜感

- 成就、装扮和工位角落。
- 稀有 Idle 动作。
- 独立可更新的社区梗文案包。
- 更多 Character Pack。

# 15. 最终判断标准

最好的版本不是她说了多少句台词、拥有多少食物或解锁多少家具，而是：

> 用户专心工作时几乎感觉不到打扰；偶尔看向角落，却能准确读懂她正在做什么。一次困难终于解决时，她先松口气，再装作一切尽在掌握。用户会笑一下，并觉得这件事是“我们一起完成的”。

这就是 dsh-dfy 应当独占的体验。
